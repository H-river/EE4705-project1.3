**Kind:**
- **behavioural**: the module does or decides something different, even when its inputs are valid.
- **robustness**: a valid input gives the same result as before; only a malformed or failing input (a bad VLM reply, a provider refusal) is now handled instead of crashing.

## Memory ownership: B (final run, stage M)

Cross-frame memory now lives in one place, Student B's planner (`planner/memory.py`, #23).
- **A** reports only what the current frame shows. Its `memory_*` attributes and `recall()` are gone (#24). Its tracks still keep the last position internally, because the tracking hint needs it to re-identify a released object.
- **B** records every LOCALIZED instance it receives: position, frame, base pose (public proprioception passed in by the runner), and whether it is held or released. When the bound goal region is out of view, B plans from the region's remembered position, within 40 frames and 0.5 m of base motion, and writes `used_memory_for` / `memory_age_frames` into its audit. B never recalls the object to grasp, because C re-observes before every GRASP, and never recalls a held or released instance. The executor then uses the plan's `params["pos"]` for MOVE_TO/PLACE. Since the region may be out of view, `validate_plan` accepts PLACE with `params["pos"]` for such a region.
- **C** keeps no memory across actions. Its disabled search-memory code is deleted (#25).

Not listed: B-only commits (`dcb962a`, `82557a9`, `0ecc0f2`) and chores (`5686bd7`, report commits), because they do not touch A's or C's code.

**Not changed on purpose:** C's `env._world` access in `_table_contacts`, which needs a public RobotEnv API. A's `memory_*` attributes: removed in #24 (memory is B's, #23).
